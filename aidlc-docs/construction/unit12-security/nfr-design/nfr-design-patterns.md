# Unit 12 — NFR Design: patterns

**Written**: 2026-09-13. **Inputs**: `nfr-requirements/nfr-requirements.md` (the values), `nfr-requirements/tech-stack-decisions.md` (the choices), `inception/application-design/unit12-security-components.md` (the parts). This document says how each part works so the two phase briefs can be written from it without re-deriving anything.

## 1. Header emission

- **Placement**: `app.UseMiddleware<SecurityHeadersMiddleware>()` directly after `app.UseForwardedHeaders()` and before the HEAD-as-GET rewrite, so every response passes through it: static assets (`MapStaticAssets` endpoints and the `/uploads` static-file middleware), the exception handler's `/Error` re-execution, the re-executed 404, the health check, the Blazor negotiate and circuit responses, the feeds and the redirects.
- **Mechanism**: `InvokeAsync` reads `SecurityOptions.CspMode` and the current `ThemeSnapshot`'s `OverrideCssHash`, composes the header list once, and registers `context.Response.OnStarting` with a callback that, for each `(name, value)`, sets the header **only when the response does not already carry it**. Then `await next(context)`. The snapshot is `themeService.LastKnown ?? await themeService.GetSnapshotAsync()`: `LastKnown` is set by a successful load or a save and survives a database outage, so once the app has served one snapshot no request touches the database for headers again — unlike a per-request `GetSnapshotAsync()` call on its own, which retries the database on every request while it stays down.
- **Why `OnStarting` and fill-if-absent**: the callback runs when the first byte is about to leave, whatever path the request took, and survives `Response.Clear()` inside the exception handler. Fill-if-absent lets a response that set its own policy earlier keep it: the `/uploads` static-file `OnPrepareResponse` sets the uploads CSP and `nosniff` before the response starts, so the page policy never overwrites them. No other code sets these headers, so on every other response the middleware's values apply.
- **Kestrel**: `builder.WebHost.ConfigureKestrel(o => o.AddServerHeader = false)` in `Program.cs` next to the other host configuration.
- **Composer** (`SecurityHeadersRules`): `Compose(CspMode mode, string? styleHash)` returns, in order, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, then the CSP under `Content-Security-Policy` (enforce) or `Content-Security-Policy-Report-Only` (report-only), or no CSP entry (off). `BuildCsp(styleHash)` joins the directives of the NFR requirements with `; `, adding `'sha256-...'` to `style-src` only when a hash is given. `UploadsCsp` is the constant string of FR-D4. Every value is a constant or a pure function of its two inputs, so the tests pin each one by string.
- **Modes**: `ParseCspMode` maps `report-only` and `off` (trimmed, case-insensitive); everything else, blank included, is `enforce`. `SecurityOptions` is built once from `IConfiguration` and registered as a singleton next to `SiteConfig`.

## 2. The theme override block under the policy

- **Hash**: `ThemeRules.BuildSnapshot` computes `OverrideCssHash` as `"sha256-" + Base64(SHA256(UTF8(OverrideCss)))`, null when `OverrideCss` is empty. `App.razor` renders the block as `<style>@((MarkupString)_theme.OverrideCss)</style>` on one line with nothing else inside the element, so the element's text is byte-identical to the hashed string. A text-scan test pins that line so a reformatting cannot silently break the hash.
- **Two readers, one snapshot**: the middleware stores the exact snapshot it used in `context.Items[SecurityHeadersMiddleware.ThemeSnapshotItemKey]`, and `App.razor` renders its override block from that request item when present, falling back to `ThemeService.GetSnapshotAsync()` only for a render the middleware never touched (tests, or any future render outside the request pipeline); a save clears the cache, and the next request's middleware call composes header and item from the same new snapshot.
- **Enhanced navigation**: Blazor patches the head in place; the block's text is unchanged between pages, so nothing is re-evaluated. After a theme save the text changes, and the first document's policy carries the old hash: the theme editor therefore forces a full load after a successful save (`NavigationManager.NavigateTo` with `forceLoad: true` back to the editor with a `saved` query flag that shows the saved notice on load), so the new header and the new block arrive together. The verification checklist walks a save followed by navigation.
- **Import map**: `<ImportMap />` is removed from `App.razor`. No module in the project imports another; `JsModuleUrl.Resolve` already hands the interop imports fingerprinted paths. With it gone, the only inline `<script>` elements are the three JSON-LD data blocks, which the browser never executes and CSP does not consult.

## 3. The theme editor without style attributes

- **Markup**: the preview frame carries `data-style="@_previewStyle"` (the same string `ThemeRules.BuildPreviewStyle` builds today) and each swatch `data-color="@_effective[token.Key]"`; no `style` attribute remains in the component.
- **Application**: `OnAfterRenderAsync` calls the color-picker module's new export `applyDataStyles(root)` on every render (the module is already imported on first render): it copies `dataset.style` into `element.style.cssText` and `dataset.color` into `element.style.background`. CSSOM writes are not governed by `style-src`, so the strict policy holds on the admin pages too.
- **Prerender**: the page prerenders on the server, so the first paint shows the frame and swatches uncolored until the circuit's first render applies them. Acceptable on an admin page; noted in the verification checklist so the owner is not surprised.
- **Pins**: `NoInlineStyleTests` scans every linked `.razor` file for `style="` and expects zero hits; a scan of the linked `colorpicker.js` expects the export and the absence of `setAttribute('style'`.

## 4. Rate limiting in the pipeline

- **Placement**: `app.UseRateLimiter()` right after `app.UseRouting()` (the per-endpoint policies need the matched endpoint) and before `app.UseAuthentication()`, so a rejection never reaches authentication, authorization, antiforgery or the analytics middleware (FR-D10, NFR-15). `ProgramPipelineTests` pins the order by scanning `Program.cs`.
- **Registration**: `builder.Services.AddRateLimiter(RateLimitPolicies.Configure)`. `Configure` sets `RejectionStatusCode = 429`, three named policies (`auth`, `feeds`, `redirects`) each partitioned by `ClientKey(context)` with a fixed-window limiter (`PermitLimit` 10 or 30, `Window` one minute, `QueueLimit` 0, `AutoReplenishment` true), the global limiter (`PartitionedRateLimiter.Create`: a path starting with `/signin-` gets a fixed-window partition keyed `signin:<address>` with the auth numbers; everything else gets `RateLimitPartition.GetNoLimiter("none")`), and `OnRejected`: read the lease's `RetryAfter` metadata (whole seconds, at least 1), set `Retry-After`, write `text/plain` "Too many requests. Try again in N seconds." The body is what keeps the status-code re-execute away from the response.
- **Client key**: `context.Connection.RemoteIpAddress`, mapped to IPv4 when it is an IPv4-mapped IPv6 address, as a string; `"unknown"` when absent. The forwarded-headers middleware has already replaced it with the trusted forwarded address when there is one.
- **Attachment**: `group.RequireRateLimiting(RateLimitPolicies.Auth)` on the `/auth` group; `.RequireRateLimiting(RateLimitPolicies.Feeds)` on `/feed.xml` and `/sitemap.xml`; `.RequireRateLimiting(RateLimitPolicies.Redirects)` on `/resume` and `/go/{id:int}/{kind}`. Nothing on `/healthz`, `/robots.txt`, `/site.webmanifest`, the owner photos, the Razor components or static files.
- **HEAD**: the HEAD-as-GET rewrite runs before routing, so a HEAD to a limited endpoint counts like a GET; its 429 body is discarded by the rewrite's null body stream, the headers stay.

## 5. Comments and reports over the circuit

- **Limiter**: `SubmissionLimiter(TimeProvider, int maxPerWindow, TimeSpan window)` is the contact limiter's per-key hit list made reusable: `Allow(key)` records a hit and answers whether the count within the window is at or under the limit; `RetryAfter(key)` is the time until the oldest hit in the window ages out. `ContactRateLimiter`, `CommentLimiter` (5 per 10 minutes) and `ReportLimiter` (3 per 10 minutes) derive from it with their numbers as constants and are singletons; the existing `ContactRateLimiterTests` stay as they are.
- **Key and exemption** (`SubmissionRules`): `IsExempt(user)` for the Admin role; `Key(userId, clientAddress)` gives `user:<id>` when signed in, else `ip:<address>`, else `ip:unknown`.
- **Services**: `CommentService.AddAsync` and `ReportService.CreateAsync` gain the caller's principal and client address; after the ban check and before any insert they return the friendly message through the existing `(entity, Error)` tuple when the limiter refuses, so `CommentSection` shows it in the same `alert` paragraphs it uses for every other refusal, and the draft text stays in the textarea.
- **Message** (`SubmissionRules.WaitMessage`): "You've posted a few comments in a row. Try again in about N minutes." (minutes rounded up, "1 minute" singular), and the same shape for reports.
- **The client address**: `BlogPostPage.razor` is static SSR and receives `HttpContext` as a cascading parameter; it passes `HttpContext.Connection.RemoteIpAddress?.ToString()` to `<CommentSection ClientAddress="..." />`. Parameters of an interactive-server island rendered by the static page travel to the circuit in a data-protected descriptor, so the browser cannot change them; the phase confirms this against the framework (the descriptor in the rendered marker is an opaque protected payload, not JSON) and records it in the plan. A reconnect reuses the original descriptor, so the value survives.

## 6. Trusted proxies

- `TrustedProxies.Parse(string? value)` splits on commas, trims, and classifies each token: an `IPNetwork` (CIDR) into `Networks`, an `IPAddress` into `Proxies`, anything else into `Skipped`. `Program.cs` applies the two lists to `ForwardedHeadersOptions` after the existing `Clear()` calls and logs one warning naming the skipped tokens. Blank produces empty lists and today's behaviour. `ForwardLimit` stays 1.
- The README's reverse-proxy section documents: the app's own headers; `TRUSTED_PROXIES` with the trade-off (blank trusts every peer's `X-Forwarded-For`); `WEB_BIND` to keep the published port off the LAN when the proxy shares the host; the single-container nature of the in-memory limits.

## 7. Verification artefacts

- `construction/build-and-test/security-verification-instructions.md`: the curl header checks, the browser CSP walk of the FR-D8 pages (with enhanced navigation and a full reload), the 429 loop, the admin-page checklist for the owner under `report-only`, and the flip to `enforce`.
- `docs/adr/0003-security-headers-are-emitted-by-the-application.md` in the repository's ADR style (a title line, one context paragraph, Considered Options, Consequences): the app sets its own headers so self-hosters without a proxy are covered; a proxy may add headers; duplicates are harmless because every CSP is enforced and frame-ancestors supersedes X-Frame-Options; the theme block is allowed by a content hash rather than a nonce because enhanced navigation keeps the first response's policy.
