# Unit 12 — Tech stack decisions

**Written**: 2026-09-13. Each decision names the alternative and why it lost. Nothing here adds a package (NFR-11).

| Decision | Chosen | Alternative | Why |
|---|---|---|---|
| Header emission | One small middleware over a pure composer, registering `Response.OnStarting` and filling only absent headers | The proxy sets the headers; or `app.Use` inline in `Program.cs` | Self-hosters have no proxy; a pure composer is unit-testable header by header; `OnStarting` survives the exception handler's response reset and covers static files, endpoints and Blazor pages alike; fill-if-absent lets the `/uploads` policy set earlier win (ADR 0003). |
| Rate limiting | `Microsoft.AspNetCore.RateLimiting` from the shared framework: named fixed-window policies on endpoints, a path-scoped global limiter for the OAuth handler paths | A custom middleware; a global limiter for everything | The framework limiter is endpoint-aware, tested, and free of packages; a global limiter over everything would count static assets and punish shared addresses (decision 5); the handler paths are not endpoints, so the path-scoped global limiter is the only way to reach them (grilling Q14). |
| Circuit actions | The generalized in-process fixed-window limiter (`ContactRateLimiter` made reusable), `TimeProvider`-driven | Framework limiter partitions called by hand from the services | Comments and reports arrive over SignalR, not as HTTP requests; the contact limiter already has the right shape and tests. |
| Theme override style block | A SHA-256 hash carried by the theme snapshot | A per-request nonce (FR-D3 as first written) | Enhanced navigation keeps the first response's policy; a fresh nonce on a later navigation never matches it, while the hash of unchanged content always does; no per-request state and no plumbing into `App.razor` (grilling Q13). |
| Inline import map | `<ImportMap />` removed | Keep it with a nonce | No module imports anything, so the map is dead weight; removing it leaves no executable inline script (`script-src 'self'` with nothing added). |
| Theme editor colors | CSSOM writes from the color-picker module after each render | `style-src-attr 'unsafe-inline'` for admin pages | One strict policy everywhere and nothing to explain in the ADR (grilling Q11); the module already sets styles through the CSSOM. |
| CSP rollout | Code default `enforce`; production's first deploy `report-only`, the owner's check, then `enforce` | `enforce` from the first deploy | The admin pages cannot be exercised before the deploy; nothing breaks under report-only while the owner checks (grilling Q7). |
| Proxy headers | The app emits `frame-ancestors 'none'` and `DENY`; the proxy is left alone | Match the proxy's `'self'` and `SAMEORIGIN`; or remove the proxy's headers | Every CSP is enforced, the stricter wins; frame-ancestors supersedes X-Frame-Options; no proxy edit needed (grilling Q8). |
| Proxy trust | `TRUSTED_PROXIES` into `KnownProxies` and `KnownIPNetworks`; blank keeps the cleared lists | Trust everything forever; or require the value | No self-hoster breaks; the owner locks production down at the 12b deploy (decision 6, Q10). |
| Limit numbers | Code constants | Env settings | One place to read and to test (decision 7); the values were settled by the owner (Q9). |
| Tests | Pure tests, middleware tests on a bare `HttpContext`, text-scan pins of `Program.cs`, a curl checklist | A test host (`Mvc.Testing`) with a migration-skipping startup path | No new package and no second startup path (grilling Q12); the suite is already built this way. |
