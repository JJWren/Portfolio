## Non-negotiables

- Inline SVG rendered by Razor from the data. No script, no CDN, no external resource, no new package (NFR-1, NFR-2, NFR-22).
- One series, daily visitors, zero baseline, no legend; the heading names it. Never a second axis.
- Colors from tokens only: the series token validated on both surfaces with the dataviz validator; text and axes in text and border tokens; nothing in `:root` changes and the 26-token theme catalog and its pinned tests stay untouched.
- No animation or transition anywhere in the chart (NFR-6); nothing `position: fixed`.
- The points sum to the tile's Daily visitors figure for the same Period (FR-V2); the chart and the tiles read the same rows.
- No owner fact in code, tests or fixtures (BR-18): test data is invented.

## What the code looks like today (evidence)

- `Stats.razor` (`@rendermode InteractiveServer`): the period select (7, 30, 90, 365, all) binds `_period` and calls `ReloadAsync`; `LoadAsync` computes `(from, to)` through `PeriodRangeAsync` (today minus N minus 1, or `FirstDayAsync` for all) and loads the summary, the routes page, the referrers and the events; the tiles grid (`.stat-tiles`) ends with `margin: 1.5rem 0 2rem` and the "Top pages" h2 follows.
- `AnalyticsService.GetSummaryAsync` sums `DailySiteStats` rows in range and adds today's live counts (`PageViews` since midnight UTC, distinct `VisitorKey`); `FirstDayAsync` returns the earliest rolled-up day or today.
- `DailySiteStat` has `Day`, `Views`, `Visitors`; one row per rolled-up day including zero days (the Watermark).
- Tokens: dark `--bg #151515`, `--surface #1d1c1a`, `--border #35322d`, `--text #e8e4dd`, `--text-muted #a49d91`, `--info #8fb6c9`, `--c-blue #6494aa`; light `--bg #f6f3ec`, `--surface #fdfbf6`, `--border #d8d1c2`, `--text #24211c`, `--text-muted #6b6459`, `--info #3f6e86`, `--c-blue` unchanged.
- Render tests use `LandingRenderHarness` (HtmlRenderer plus a service collection) and `AppCssTests` parse `app.css` leaf rules through `CssScanner`. The dataviz validator is `scripts/validate_palette.js` in the skill folder; node 22 is installed.
- No development sign-in exists, so `/admin/stats` cannot be driven locally through the UI; the chart component is rendered in tests with fixed data, and the "render and look" step runs the component in a throwaway page or the local app with synthetic rows (the brief says how).

## Deviations

Ticks yields two gridlines when NiceMax is 1 or 5 (a week whose busiest day has at most five visitors), a documented exception to FR-V6's three to five, pinned by `Ticks_SmallestScales_ReturnJustTheEndpoints`.
- Hit columns are exactly the spacing between neighbouring points rather than "at least 6 units" (FR-V8 says only "wider than the mark"): at 365 points a 6-unit minimum made later columns capture the pointer over earlier days, so each day owns just its own half-way boundaries (about 1.8 units at 365 points). The tooltip box is sized from its monospace text instead of a fixed width, so a large count never leaves the frame. Both from Copilot round 1 on PR #106.
- Copilot round 3 on PR #106: `NiceMax` uses long arithmetic and clamps at the int maximum (a count near the limit overflowed the candidate); an endpoint hit column is clamped to the plot so a two-point chart tiles instead of the second column covering the first; the axis top is computed once per render; `WithTodayFromTotal` re-derives today from the Daily visitors tile after every tile reload so the chart keeps summing to it on sort and pager clicks; `LinePath` takes a `lastIsToday` flag (the phase agent deviation, now in the Components table). Declined: bucketing or bounding the All time series (decision 21, one point per day, is the owner call; NFR-24 notes the consequence).
