## Deviations

Phase 12a, recorded by the phase agent:

- **Framework defaults fought the middleware (fix commit 837a6fb).** Neither this plan nor the NFR design anticipated that ASP.NET Core itself sends baseline anti-clickjacking headers: antiforgery generation sends `X-Frame-Options: SAMEORIGIN` unconditionally by default, and `AddInteractiveServerRenderMode()` sends `Content-Security-Policy: frame-ancestors 'self'` by default on interactive component responses (both confirmed against Microsoft Learn). Because both are written deep in endpoint execution, their `Response.OnStarting` registration happens after `SecurityHeadersMiddleware`'s and so fires first (`OnStarting` runs last-registered-first); `SecurityHeadersMiddleware`'s fill-if-absent then found the header already present and kept the framework's weaker value on every interactive page. Curl against a bare minimal-API endpoint (`/feed.xml`, unaffected) versus `/` and the 404 page (affected) is what surfaced the split. Fixed at the documented source instead of adding path-based special-casing to the middleware: `AntiforgeryOptions.SuppressXFrameOptionsHeader = true` and `ServerComponentsEndpointOptions.ContentSecurityFrameAncestorsPolicy = null`, both narrowly scoped, both existing precisely so an app supplying its own policy (as this one does, on every response, first render included) can turn the partial defaults off. Reverified with curl and the browser console after the fix.
- **Commit order swapped relative to the brief's list.** The brief lists the `feat:` commits as "the composer, options and middleware with the Program.cs wiring" then "the snapshot hash and the ImportMap removal", but `SecurityHeadersMiddleware.InvokeAsync` reads `ThemeSnapshot.OverrideCssHash`, so the middleware commit cannot build without the hash already existing. Committed the hash/ImportMap change first (5f5cca7), then the composer/options/middleware/wiring (f7da30e), keeping every commit individually green under `dotnet build -warnaserror` and `dotnet test` as required.
- **`SecurityHeadersMiddleware.cs` lives in `Services/`, not a new `Middleware/` folder.** The application-design doc (`inception/application-design/unit12-security-components.md`) sketches `Middleware/SecurityHeadersMiddleware.cs`, but the brief's own "Implementation notes" and "the files you change" sections say it sits beside `AnalyticsMiddleware.cs` — which already lives in `Services/`. Followed the brief and the existing convention.
- **A sixth commit (`fix:`) was added** beyond the brief's five, for the framework-defaults fix above; `fix:` is an established prefix in this repository's history (e.g. PR #107) and NFR-12's "allow-list" concern is about the PR title, not every commit inside it.

Phase 12a review remediation, recorded by the remediation agent (commits f21a307, e82b574):

- **Two more headers added: `X-DNS-Prefetch-Control: off` and `X-Permitted-Cross-Domain-Policies: none` (commit f21a307).** Neither was in FR-D1's named list or this plan's non-negotiables; a security review flagged both as the same shape of "deny a legacy capability nothing here uses" as the rest of section 1 (DNS prefetching leaking hostnames the page merely mentions; a legacy Flash/Acrobat cross-domain policy file). Emitted by `Compose` after `Cross-Origin-Opener-Policy` and before the CSP entry.
- **`Permissions-Policy` grew from 13 to 19 denied features (commit f21a307).** A security review named `autoplay`, `clipboard-read`, `clipboard-write`, `fullscreen`, `picture-in-picture` and `web-share` as further powerful features the site never uses; added in alphabetical order alongside the original 13. `nfr-requirements.md` section 1 and the verification checklist updated to match.
- **Composed headers are cached instead of recomposed every request (commit f21a307).** Neither this plan nor the NFR design called out per-request composition cost; a performance review noted `Compose` ran on every response, static assets included, even though the CSP mode is fixed for the process and the theme's style hash changes only on a save. `SecurityHeadersMiddleware` now keeps the last `(hash, headers)` pair in a field and recomposes only on a hash miss.
- **The saved notice moved from `OnInitializedAsync` to `OnAfterRenderAsync` (commit f21a307).** Neither this plan nor the NFR design considered screen-reader announcement: a `role="status"` live region announces a DOM mutation inserted after load, never a notice already present in the prerendered markup. Trade-off accepted: the page is briefly visible without the notice until that render's `StateHasChanged()` patches it in.
- **`ResetAllAsync` now forces the same full-page reload `SaveAsync` does (commit f21a307).** Not anticipated by this plan: a reset persists the cleared overrides through the same `PersistAsync` path a save uses, so without the reload the open document kept whatever override CSP hash it had loaded with even after the overrides (and the hash) were gone. Factored into a shared `ReloadWithSavedNotice` helper called after both a successful save and a successful reset.
