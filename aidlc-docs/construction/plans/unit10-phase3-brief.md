## Implementation notes the plan does not spell out

- **`Belt` enum** in `BjjRules.cs`: `White, Blue, Purple, Brown, Black` in ladder order, with `ParseBelt(string)` (trim, case-insensitive) returning null for anything else, and `CssName(Belt)` returning the lowercase class name (`white`, `blue`, `purple`, `brown`, `black`) matching `--rank-*`.
- **Records**: `Era(DateOnly Date, Belt Belt, int Stripes, string Gym, string Location, string Role)` and `NowItem(string Label, string Value)`; `Rung(Belt Belt, int Stripes)` for the ladder (one per distinct belt in first-appearance order, stripes from the LAST era of that belt, BR-8).
- **Parsing** (lenient at resolve, BR-4): `ParseEras(lines)` splits six fields (`date | belt | stripes | gym | location | role`); `date` must parse with `DateOnly.TryParseExact(..., "yyyy-MM-dd", CultureInfo.InvariantCulture, ...)`; `belt` through `ParseBelt`; `stripes` blank means 0, otherwise an integer 0 to `MaxDegrees`; gym, location, role may be blank; malformed lines are dropped; more than `MaxEras = 12` lines truncates to the first twelve; the LAST field (`role` here, `value` for Now) absorbs any extra `|` by re-joining with " | " exactly like Phase 2 does through `BjjRules.TailField`, so free text with a pipe is kept whole rather than cut. `ParseNow(lines)` splits two fields, label required, value may be blank, cap `MaxNowItems = 8`. Order is preserved exactly as entered.
- **Validation** (strict at save): `ValidateEras(lines)` returns the first problem with the one-based line number ("Eras line 3: belt must be white, blue, purple, brown or black", "Eras line 2: date must be YYYY-MM-DD", "Eras line 4: stripes must be 0 to 6", "Eras: at most 12 lines", "line longer than 500 characters"); `ValidateNow(lines)` similarly; `ValidateDegreesAgainstEras(int? degrees, IReadOnlyList<Era> eras)` implements BR-9: when degrees is set and a black-belt era exists (use the last black era), its stripes must equal degrees, else "Belt degrees (0) and the black belt era's stripes (1) disagree".
