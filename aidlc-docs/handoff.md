## 6. Execution model and mechanics that mattered this session

- **Orchestration** (owner instruction 2026-09-04): the main session orchestrates; one fresh Sonnet general-purpose phase agent per phase, briefed from a self-contained brief file (template: `construction/plans/unit14-brief.md` or `unit10-phase5-brief.md`); five report-only review agents (correctness, security with the BR-18 grep, framework and accessibility, maintainability, performance); a remediation agent for a long list or the orchestrator for a few one-line fixes; then PR, Copilot gate, squash-merge. Agents commit on the branch by explicit path and never push; they never touch `audit.md` or `aidlc-state.md`.
- **Gates**: every stage gate is presented and logged in `audit.md` with the owner's verbatim answer; the construction completion message is the 2-option one. On 2026-09-11 the owner pre-approved the Unit 14 gates with "Continue through with the requests from this session until complete and then deploy"; that instruction does not extend to Units 11 and 12.
- **Copilot**: request with `env -u GITHUB_TOKEN gh api -X POST repos/JJWren/Portfolio/pulls/N/requested_reviewers -f "reviewers[]=copilot-pull-request-reviewer[bot]"`; the response lists no reviewer because Copilot accepts at once, so read the issue timeline (`review_requested`, `copilot_work_started`). A re-request made while a review is in progress is absorbed, so re-request after the review lands. A thread reply from this machine is recorded as a review by the repository account, so a gate monitor must filter on the bot login. "Needs a closer look" with zero new comments is a clean pass; suppressed notes are worth reading anyway.
- **Git**: `env -u GITHUB_TOKEN gh ...` (the session token is invalid; the keyring login has the scope). GitHub auto-deletes merged head branches. Stash-first realign (`git stash push --include-untracked`, `git reset --hard origin/master`, `git stash pop`). When two open PRs touch the same doc line (this session: the coverage heading), merge `origin/master` into the branch and resolve; squash-merge hides the merge commit. For a side change while a phase agent works, use a separate worktree (`git worktree add <dir> -b <branch> origin/master`).
- **Bash on this machine**: doubled backslashes collapse even in single quotes, so code goes through Write and Edit, never heredocs, sed or perl; jq expressions with regex escapes fail the same way. Most files are CRLF (`unix2dos` new docs; `printf '%s\r\n'` to append; perl line edits with the file's own EOL). `dotnet test` gates: `grep -q "Failed:     0,"`.
- **Production** (this machine, Docker Desktop, context desktop-linux): `Z:\docker\portfolio` (`/z/docker/portfolio` in Git Bash) holds `docker-compose.yml` (LF; the image tag is bumped by hand) and `.env` (CRLF, secrets: inspect only with values masked, never `cat`). Deploy: bump the tag, `docker compose pull web`, `docker compose up -d web`; `docker ps -a --filter name=portfolio` (a plain `docker ps | head` can hide the two containers below other projects' test stacks). Database queries for a fact: `docker exec portfolio-db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "..."'` (the role is not the default `portfolio`; aggregates only, no personal data).
